# Project collaboration

- Keep substantive requirements, research, plans, architecture decisions, and discussion outcomes in `docs/` for future reference, as requested by the user.
- Distinguish user-confirmed requirements from proposals, assumptions, and unresolved questions.
- Update the relevant document and `docs/discussion-log.md` when a decision changes. Preserve useful rationale and source links.
- Do not record credentials, API keys, private customer data, or hidden internal reasoning in documentation.
- The user authorized assignment implementation after accepting the discussed direction. Keep code readable and maintain architecture/setup documentation. Distinguish implemented behavior, accepted direction and remaining proposals; do not present deferred features as complete.
